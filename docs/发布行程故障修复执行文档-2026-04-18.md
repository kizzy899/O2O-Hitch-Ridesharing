# 发布行程故障修复执行文档（2026-04-18）

## 1. 问题现象
- 前端在“发布行程”步骤提交后返回：
  - `PASSENGER_PROFILE_UNAVAILABLE`
  - 响应码：`5005`
- 影响：
  - 乘客侧流程在“发布行程”阶段中断，后续订单流程无法继续。

## 2. 根因定位
- `trip-service` 在创建行程前会调用 `passenger-service` 查询乘客档案。
- 对新注册乘客，系统只完成了认证与用户注册，没有自动补齐乘客档案。
- 因此 `POST /api/trips` 在校验阶段失败并抛出 `PASSENGER_PROFILE_UNAVAILABLE`。

### 证据链
1. 新用户注册成功后直接调用 `POST /api/trips`，稳定复现 `5005/PASSENGER_PROFILE_UNAVAILABLE`。
2. 同一用户先调用 `POST /api/passengers` 补档案，再调用 `POST /api/trips` 可成功返回 `tripId`。

## 3. 修复方案
- 在前端“发布行程”关键路径前增加“乘客档案补齐”动作，保证行程发布前置条件满足：
  1. 流程控制台：
     - 步骤 2（乘客登录）成功后，自动调用 `/api/passengers` 补齐档案。
     - 步骤 3（发布行程）执行前，再做一次兜底补档案。
  2. 右侧真实业务页：
     - 发布行程提交前，先调用 `/api/passengers` 再调用 `/api/trips`。
- 在前端 API 层新增统一方法：
  - `upsertPassengerProfile(passengerId, level, emergencyContact)`

## 4. 代码变更清单
- `frontend/src/api/index.ts`
  - 新增 `upsertPassengerProfile(...)`，请求 `POST /passengers`。
- `frontend/src/console/FlowConsolePanel.tsx`
  - 步骤 2 登录后自动补齐乘客档案。
  - 步骤 3 发布前兜底补档案。
- `frontend/src/app/passenger/PassengerPublishTripPage.tsx`
  - 提交发布前自动补齐乘客档案。
- `frontend/src/__tests__/api.spec.ts`
  - 新增 `upsertPassengerProfile` 调用契约测试。

  - `npm --prefix frontend test -- api.spec.ts flow.spec.ts route-sync.spec.ts`

- 结果：
  - 单测通过（15 passed）
  - 构建通过（Vite build success）

### 接口联调复现与验证
1. 复现失败路径：
   - `注册 -> 直接发布行程`
   - 结果：`5005/PASSENGER_PROFILE_UNAVAILABLE`
2. 验证修复逻辑：
   - `注册 -> 补档案(/api/passengers) -> 发布行程(/api/trips)`
   - 结果：发布成功并返回 `tripId`

## 6. 执行结论
- 问题根因明确，已通过“前置补档案 + 发布前兜底”闭环修复。
- 发布行程链路已恢复可用，且具备回归测试覆盖，后续可复用该执行流程进行排障。
