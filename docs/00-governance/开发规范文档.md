# 开发规范文档

## 1. 分层规范
- Controller：请求接收、参数校验、响应封装。
- Service：业务逻辑与编排。
- Client：跨服务调用。
- Config：配置与中间件装配。
- Exception：异常定义。
- DTO/VO/Entity：输入输出与实体结构。

## 2. 代码组织原则
- 单一职责：类与方法聚焦单一职责。
- 显式依赖：通过构造器注入依赖。
- 统一入口：外部调用必须通过网关。
- 统一返回：使用 `ApiResponse`。

## 3. 控制器约束
- 路径资源化命名，不使用无语义路径。
- 参数使用 `@PathVariable/@RequestBody/@RequestParam` 明确声明。
- Controller 不直接写复杂业务逻辑。

## 4. 服务层约束
- service 负责业务规则和跨服务调用编排。
- 异常通过 `BusinessException` 抛出。

## 5. 审查清单
- 是否遵守分层。
- 是否有统一返回体。
- 是否有异常分支处理。
- 是否补齐文档。
