# 08 综合业务流程

## 本阶段目标
- 打通主链路：登录 -> 发布行程 -> 创建订单 -> 司机接单 -> 完成/取消 -> 查询订单。
- 补齐查询链路：支持我的行程列表与我的订单列表按状态筛选。

- `auth-service`

- `passenger-service`

## 核心类与配置说明
- 路由由 `config-repo/gateway-zuul.yml` 管理。
- 统一认证参数由 `config-repo/application.yml` 管理。
- 认证服务通过 Feign 查询用户认证资料。
- 行程服务创建前通过 Feign 查询乘客档案，保障链路包含乘客模块。
- 订单服务创建前校验行程归属与司机可接单状态。
- 订单接单后联动行程服务将状态推进到 `ORDER_ACCEPTED`，并联动司机服务将可接单状态更新为 `false`。
- 订单完成或取消后联动行程状态推进，并按规则恢复司机可接单状态。
- 网关透传 `X-User-Id`、`X-User-Role` 后，订单与行程接口执行用户作用域校验，避免越权查询与越权提交。
- 在订单接单、完成、取消与详情查询环节执行订单归属校验，保证司机/乘客仅可操作本人订单。
- 在行程详情查询环节执行行程归属校验，保证普通乘客仅可查询本人行程。
- 在司机绑定行程环节执行司机作用域校验，保证司机仅可绑定本人身份。

## 模块之间调用关系
- 客户端 -> 网关 -> 业务服务
- auth -> user（Feign）
- trip -> passenger（Feign）
- trip -> user（Feign）
- order -> trip（Feign）
- order -> driver（Feign + Ribbon）

## 文字版流程说明
1. 用户登录获取 token。
2. 乘客携带 token 完成乘客档案写入。
3. 乘客携带 token 发布行程，行程服务先校验乘客档案，再创建 `PUBLISHED` 行程。
4. 乘客创建订单，订单服务先校验行程归属与司机状态，再生成 `PENDING_ACCEPT` 订单。
5. 司机执行接单，订单状态推进到 `ACCEPTED`，并联动行程状态推进到 `ORDER_ACCEPTED`，司机可接单状态更新为 `false`。
6. 司机完成订单时，订单状态推进到 `COMPLETED`，行程状态推进到 `ORDER_COMPLETED`，司机可接单状态恢复为 `true`。
7. 任一方取消订单时，订单状态推进到 `CANCELLED`，行程状态推进到 `ORDER_CANCELLED`，已接单场景司机可接单状态恢复为 `true`。
8. 乘客查询行程列表时，可按状态筛选查看当前阶段行程。
9. 乘客或司机查询订单列表时，可按状态筛选查看当前阶段订单。
