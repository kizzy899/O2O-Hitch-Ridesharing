# 07 统一认证与授权

## 本阶段目标
- 建设统一登录、统一验签、统一身份透传能力。
- 建设认证服务与用户资料联动校验能力。

## 涉及模块
- `auth-service`
- `gateway-zuul`
- `user-service`
- `trip-service`
- `order-service`
- `common`

## 对应关键代码位置
- `auth-service/src/main/java/com/o2o/hitch/auth/controller/AuthController.java`
- `auth-service/src/main/java/com/o2o/hitch/auth/service/AuthService.java`
- `auth-service/src/main/java/com/o2o/hitch/auth/client/AuthUserClient.java`
- `gateway-zuul/src/main/java/com/o2o/hitch/gateway/filter/AuthPreFilter.java`
- `user-service/src/main/java/com/o2o/hitch/user/controller/UserController.java`

## 核心类与配置说明
- 登录接口通过用户服务认证资料完成账号口令校验。
- 登录成功后签发 JWT（包含 `userId` 与 `role`）。
- 网关统一验签并透传 `X-User-Id`、`X-User-Role`。
- 业务服务按角色控制关键接口访问，并在订单/行程查询与创建场景执行用户作用域校验（普通乘客仅可访问本人数据，管理员可跨用户操作）。
- 订单服务在接单、完成、取消、详情查询场景追加订单归属校验，阻止跨用户操作。
- 行程服务在详情查询场景执行行程归属校验，阻止普通乘客读取他人行程。
- 行程服务在司机绑定场景执行司机作用域校验，阻止司机绑定非本人 `driverId`。

## 关键接口说明
1. `POST /api/auth/login`
2. `GET /api/auth/me`
3. `GET /users/internal/{userId}/auth-profile`（认证服务内部调用）

## 模块之间调用关系
- `auth-service -> user-service`（Feign）
- `gateway-zuul -> 业务服务`（统一鉴权转发）

## 文字版流程说明
1. 用户提交账号与口令。
2. 认证服务查询用户认证资料并校验。
3. 校验通过后签发 token。
4. 后续请求由网关完成统一验签并透传身份。
5. 业务服务按角色执行授权判断。

## 本阶段能力结果
- 系统具备统一认证入口、统一验签、统一身份透传与业务侧角色控制能力。
